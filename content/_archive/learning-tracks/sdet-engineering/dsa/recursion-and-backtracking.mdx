# Recursion and Backtracking

> **Module:** 01-programming-foundations / dsa
> **Prerequisites:** Stacks And Queues, Complexity Analysis
> **Mastery Target:** L3

---

## Quick Overview (2-minute read)

**What:** Recursion is a function calling itself with a smaller input until it reaches a base case. Backtracking extends recursion by exploring all possibilities, choosing an option, recursing, then undoing the choice to try the next option.

**Why:** Recursion is the foundation for tree/graph traversal, divide-and-conquer algorithms, and many interview problems. Backtracking solves combinatorial problems (subsets, permutations) that appear in interviews and in test generation scenarios.

**Where:** Tree traversals, merge sort, Fibonacci, generating test combinations, subset/permutation generation, constraint satisfaction problems.

<MentalModel>

**Recursion** — Think of Russian nesting dolls. Each doll opens to reveal a smaller doll inside, until you reach the smallest one (base case). Then you close them back up (return from each call).

</MentalModel>


**Backtracking** — Think of navigating a maze. At each fork, you pick a path. If it's a dead end, you back up to the fork and try the next path. You systematically try all options.

<KeyTakeaways>

1. Every recursive function needs a **base case** (when to stop) and a **recursive case** (how to make progress toward the base case).
2. Each recursive call adds a frame to the **call stack** — too many calls cause `StackOverflowError`.
3. **Memoization** caches results of expensive recursive calls to avoid redundant computation.
4. Backtracking follows the **choose-explore-unchoose** pattern: add to current state, recurse, then remove from current state.
5. Backtracking generates all combinations/permutations in O(2^n) or O(n!) — these are inherently expensive but sometimes necessary.

</KeyTakeaways>

## Key Patterns and Techniques

### Recursion Anatomy


```java
public int recursiveFunction(int n) {
    // 1. BASE CASE — stop condition
    if (n <= 0) return 0;

    // 2. RECURSIVE CASE — call with smaller input
    return n + recursiveFunction(n - 1);
}
```

### Pattern 1: Fibonacci — Naive vs Memoized


```java
// NAIVE: O(2^n) time — recalculates the same values repeatedly
public int fibNaive(int n) {
    if (n <= 1) return n;
    return fibNaive(n - 1) + fibNaive(n - 2);
}
// fib(5) calls fib(4) + fib(3)
//   fib(4) calls fib(3) + fib(2) ← fib(3) computed AGAIN
//   Exponential explosion of redundant calls

// MEMOIZED: O(n) time — each value computed once
public int fibMemo(int n, Map<Integer, Integer> memo) {
    if (n <= 1) return n;
    if (memo.containsKey(n)) return memo.get(n);

    int result = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    memo.put(n, result);
    return result;
}

// ITERATIVE (bottom-up): O(n) time, O(1) space — best for production
public int fibIterative(int n) {
    if (n <= 1) return n;
    int prev2 = 0, prev1 = 1;
    for (int i = 2; i <= n; i++) {
        int curr = prev1 + prev2;
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}
```

### Pattern 2: Backtracking Template (Choose-Explore-Unchoose)


```java
public void backtrack(List<List<Integer>> result, List<Integer> current,
                      int[] nums, int start) {
    result.add(new ArrayList<>(current)); // record current state

    for (int i = start; i < nums.length; i++) {
        current.add(nums[i]);            // CHOOSE
        backtrack(result, current, nums, i + 1); // EXPLORE
        current.remove(current.size() - 1);      // UNCHOOSE (backtrack)
    }
}
```

### Understanding the Call Stack


```java
// Each call creates a stack frame with local variables
factorial(4)
  → factorial(3)        // frame 2 added to stack
    → factorial(2)      // frame 3 added
      → factorial(1)    // frame 4 added
        → returns 1     // frame 4 popped
      → returns 2 * 1   // frame 3 popped
    → returns 3 * 2     // frame 2 popped
  → returns 4 * 6       // frame 1 popped
// Maximum stack depth: 4 frames → O(n) space
```

## Problems with Solutions

### Problem 1: Fibonacci with Memoization

**Task:** Compute the nth Fibonacci number efficiently.

**Hint:** Start with the naive recursive solution, then add a HashMap to cache computed values.




```java
public int fib(int n) {
    return fibHelper(n, new HashMap<>());
}

private int fibHelper(int n, Map<Integer, Integer> memo) {
    if (n <= 1) return n;
    if (memo.containsKey(n)) return memo.get(n);

    int result = fibHelper(n - 1, memo) + fibHelper(n - 2, memo);
    memo.put(n, result);
    return result;
}
// Time: O(n) | Space: O(n) for memo + call stack
```



### Problem 2: Subsets (LeetCode 78)

**Task:** Given an integer array of unique elements, return all possible subsets (the power set).

**Hint:** Use the backtracking template. At each index, you either include or skip the element. Start from index 0, and for each recursive call, move to the next index.




```java
public List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    backtrack(result, new ArrayList<>(), nums, 0);
    return result;
}

private void backtrack(List<List<Integer>> result, List<Integer> current,
                        int[] nums, int start) {
    result.add(new ArrayList<>(current)); // add a COPY, not the reference

    for (int i = start; i < nums.length; i++) {
        current.add(nums[i]);                    // choose
        backtrack(result, current, nums, i + 1); // explore
        current.remove(current.size() - 1);      // unchoose
    }
}
// Time: O(n * 2^n) | Space: O(n) recursion depth
```



### Problem 3: Permutations (LeetCode 46)

**Task:** Given an array of distinct integers, return all possible permutations.

**Hint:** Similar to subsets but use a `used` boolean array instead of a start index. Each position can use any unused element.




```java
public List<List<Integer>> permute(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    backtrackPermute(result, new ArrayList<>(), nums, new boolean[nums.length]);
    return result;
}

private void backtrackPermute(List<List<Integer>> result, List<Integer> current,
                               int[] nums, boolean[] used) {
    if (current.size() == nums.length) {
        result.add(new ArrayList<>(current));
        return;
    }

    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;

        used[i] = true;                                    // choose
        current.add(nums[i]);
        backtrackPermute(result, current, nums, used);     // explore
        current.remove(current.size() - 1);                // unchoose
        used[i] = false;
    }
}
// Time: O(n * n!) | Space: O(n)
```



### Problem 4: N-Queens (Concept Only)

**Task:** Place n queens on an n x n chessboard such that no two queens attack each other.

**Concept:** This is the classic backtracking problem. Place queens row by row. For each row, try each column. Check if the placement is valid (no queen in same column, same diagonal). If valid, recurse to the next row. If no valid placement exists, backtrack.

**Why concept-only:** The full implementation is complex and rarely asked in SDET interviews, but understanding the approach demonstrates mastery of backtracking.

## Common Mistakes

### Mistake 1: Missing or Wrong Base Case


```java
// WRONG: no base case — infinite recursion → StackOverflowError
public int factorial(int n) {
    return n * factorial(n - 1); // never stops!
}

// RIGHT: base case stops the recursion
public int factorial(int n) {
    if (n <= 1) return 1; // base case
    return n * factorial(n - 1);
}
```

### Mistake 2: Adding the Reference Instead of a Copy


```java
// WRONG: all entries in result point to the SAME list (which ends up empty)
result.add(current);

// RIGHT: add a copy of the current state
result.add(new ArrayList<>(current));
```

**Why:** The `current` list is modified as backtracking continues. Without copying, all entries in `result` reference the same mutated list.

### Mistake 3: Not Understanding Stack Depth Limits


```java
// DANGEROUS: Java default stack size handles ~5,000-10,000 frames
public void deepRecursion(int n) {
    if (n == 0) return;
    deepRecursion(n - 1); // n = 100,000 → StackOverflowError
}

// FIX: convert to iteration for deep recursion, or increase stack size with -Xss flag
```

## Automation Connections

| Concept | Automation Use Case |
|---|---|
| Recursion | Traversing nested JSON/XML structures for validation |
| Backtracking (subsets) | Generating test data combinations from input domains |
| Permutations | Generating all orderings to test order-dependent behavior |
| Memoization | Caching expensive test fixture computations |
| Call stack understanding | Reading and debugging stack traces |


```java
// Example: Generate all test parameter combinations
public static List<Map<String, String>> generateCombinations(
        Map<String, List<String>> paramDomains) {
    List<Map<String, String>> result = new ArrayList<>();
    List<String> keys = new ArrayList<>(paramDomains.keySet());
    backtrackCombos(result, new HashMap<>(), keys, paramDomains, 0);
    return result;
}

private static void backtrackCombos(List<Map<String, String>> result,
        Map<String, String> current, List<String> keys,
        Map<String, List<String>> domains, int index) {
    if (index == keys.size()) {
        result.add(new HashMap<>(current));
        return;
    }
    String key = keys.get(index);
    for (String value : domains.get(key)) {
        current.put(key, value);
        backtrackCombos(result, current, keys, domains, index + 1);
        current.remove(key);
    }
}
```

## Interview and Revision




**Q:** What are the two essential parts of every recursive function?
**A:** Base case (stopping condition) and recursive case (calling itself with a smaller/simpler input that progresses toward the base case).

**Q:** What is the time complexity of naive Fibonacci recursion, and how does memoization fix it?
**A:** Naive: O(2^n) due to redundant recalculations. Memoization: O(n) by caching each value so it's computed only once.

**Q:** What is the choose-explore-unchoose pattern?
**A:** The backtracking template: (1) add an element to the current state (choose), (2) recurse to explore further (explore), (3) remove the element to try the next option (unchoose/backtrack).

**Q:** Why do you need `new ArrayList<>(current)` when adding to results in backtracking?
**A:** Because `current` is modified throughout the recursion. Without copying, all entries in the result list would reference the same (eventually empty) list object.
