# StayNest - Implementation Milestones

> **Module:** 11 — StayNest Lab
> **Prerequisites:** First Lab, Test Scenarios, Architecture
> **Purpose:** Progressive plan to build automation coverage across all layers — API, web UI, mobile, and CI

## Overview

This document is your roadmap from "first test passes" to "complete automation suite running in CI." Each milestone builds on the previous one. Don't skip ahead — the milestones are sequenced so that earlier work becomes the foundation for later work.

**Total estimated time:** 8-12 weeks (part-time, ~10 hours/week)

## Milestone 1: API Smoke Tests (Auth)

**Goal:** Verify that the StayNest backend is alive and the two most critical flows work: signup and login.

**Estimated Time:** 4-6 hours

### Objectives

- Set up a Maven project with REST Assured, TestNG, and Jackson
- Write a reusable base test class with config management
- Create 5 smoke tests for signup and login
- Establish test naming conventions and logging

### Prerequisites

- [ ] Java 21 JDK installed
- [ ] Maven 3.9+ installed
- [ ] StayNest backend running on `localhost:8080`
- [ ] Completed First Lab (provides step-by-step guidance for this milestone)

### Tests to Write

| Test ID | Test | Business Rule | Assertion |
| --- | --- | --- | --- |
| API-AUTH-01 | Signup with valid data | AUTH-01 | 201, response has `id`, `email`, `name`, no `password` |
| API-AUTH-02 | Login with valid credentials | AUTH-05 | 200, response has `accessToken` (valid JWT) |
| API-AUTH-03 | Login with wrong password | AUTH-07 | 401 |
| API-AUTH-05 | Signup with duplicate email | AUTH-02 | 500 with "already present" message |
| API-AUTH-06 | Signup without email | VAL-01 | 400 with "Email is required" in subErrors |

### Project Structure at This Point

```
staynest-api-tests/
  src/test/java/
    com/staynest/tests/
      base/
        BaseApiTest.java         # REST Assured config, logging
      auth/
        SignupTest.java          # 3 signup tests
        LoginTest.java           # 2 login tests
  src/test/resources/
    config.properties            # base URL, timeouts
  pom.xml
  testng.xml
```

### Success Criteria

- [ ] All 5 tests pass when the backend is running
- [ ] Tests use unique emails (UUID-based) so they're repeatable without cleanup
- [ ] Base test class configures REST Assured base URI from properties file
- [ ] Test output shows clear pass/fail with descriptive test names
- [ ] Tests run via `mvn test` and produce a TestNG report

protected Long createHotelAndActivate(String token, String city) {
    Long hotelId = given()
        .header("Authorization", "Bearer " + token)
        .contentType(ContentType.JSON)
        .body(Map.of("name", "Test Hotel " + UUID.randomUUID(), "city", city))
    .when()
        .post("/admin/hotels")
    .then()
        .statusCode(201)
        .extract().jsonPath().getLong("data.id");

    .when()
        .patch("/admin/hotels/" + hotelId + "/activate")
    .then()
        .statusCode(204);

    return hotelId;
}

## Milestone 3: API Integration Tests (Full Booking Lifecycle)

**Goal:** Test complete business flows that span multiple endpoints. This is where you catch integration bugs that unit tests and CRUD tests miss.

**Estimated Time:** 6-8 hours

### Objectives

- Write end-to-end booking lifecycle test (init → addGuests → payment → cancel)
- Write negative lifecycle tests (cancel without payment, expired bookings)
- Add database validation (optional — connect to PostgreSQL and verify state)
- Introduce JSON schema validation for response structure

### Prerequisites

- [ ] Milestone 2 completed and passing
- [ ] Understanding of booking lifecycle from Requirements And Business Rules

### Tests to Write

| Test ID | Test | Flow | Assertion |
| --- | --- | --- | --- |
| INT-01 | Full booking lifecycle | init → addGuests → payment → confirm → cancel | Each step returns expected status; final status is CANCELLED |
| INT-02 | Cancel without payment | init → cancel (skip payment) | 409 "Only confirmed bookings can be cancelled" |
| INT-03 | Add guests to non-RESERVED booking | init → payment → addGuests | 409 "Booking is not under reserved state" |
| INT-04 | Book with no inventory | init twice for same room (totalCount=1) | First: 200, Second: 409 |
| INT-05 | Search → book → verify inventory | search → pick hotel → book → search again | Available rooms decrease |
| INT-06 | Cross-user access | User A books → User B tries to cancel | 403 |
| INT-07 | Schema validation | Any endpoint | Response matches JSON schema |

### New Code to Add


```java
// Full lifecycle test
@Test
public void shouldCompleteFullBookingLifecycle() {
    // Setup: create manager, hotel, room, guest user
    String managerToken = loginAsManager();
    Long hotelId = createHotelAndActivate(managerToken, "New York");
    Long roomId = createRoom(managerToken, hotelId, "DELUXE", 150.00, 10);

    String guestToken = loginAsGuest();
    Long guestId = createGuest(guestToken, "John Doe", "MALE", "1990-01-01");

    // Step 1: Init booking → RESERVED
    Long bookingId = initBooking(guestToken, hotelId, roomId, checkIn, checkOut, 1);
    assertBookingStatus(guestToken, bookingId, "RESERVED");

    // Step 2: Add guests → GUESTS_ADDED
    addGuests(guestToken, bookingId, List.of(guestId));
    assertBookingStatus(guestToken, bookingId, "GUESTS_ADDED");

    // Step 3: Payment → CONFIRMED (mock mode)
    initiatePayment(guestToken, bookingId);
    assertBookingStatus(guestToken, bookingId, "CONFIRMED");

    // Step 4: Cancel → CANCELLED
    cancelBooking(guestToken, bookingId);
    assertBookingStatus(guestToken, bookingId, "CANCELLED");
}
```

### Success Criteria

- [ ] 7+ integration tests passing, covering happy and unhappy lifecycle paths
- [ ] Full booking lifecycle test runs end-to-end in under 10 seconds
- [ ] At least one test validates cross-user authorization
- [ ] Response schema validation added for at least the booking endpoint
- [ ] Tests document the exact business rules they verify (comments or test names)

### Key Code Pattern: Page Object


```java
public class LoginPage {
    private final WebDriver driver;
    private final WebDriverWait wait;

    @FindBy(css = "[data-testid='email-input']")
    private WebElement emailInput;

    @FindBy(css = "[data-testid='password-input']")
    private WebElement passwordInput;

    @FindBy(css = "[data-testid='login-button']")
    private WebElement loginButton;

    @FindBy(css = "[data-testid='error-message']")
    private WebElement errorMessage;

    public LoginPage(WebDriver driver) {
        this.driver = driver;
        this.wait = new WebDriverWait(driver, Duration.ofSeconds(10));
        PageFactory.initElements(driver, this);
    }

    public void login(String email, String password) {
        wait.until(ExpectedConditions.visibilityOf(emailInput));
        emailInput.clear();
        emailInput.sendKeys(email);
        passwordInput.clear();
        passwordInput.sendKeys(password);
        loginButton.click();
    }

    public String getErrorMessage() {
        wait.until(ExpectedConditions.visibilityOf(errorMessage));
        return errorMessage.getText();
    }
}
```

### Success Criteria

- [ ] 4 UI smoke tests passing in both headed and headless modes
- [ ] Page objects encapsulate all locators (tests don't contain `By.xxx` calls)
- [ ] Screenshots captured automatically on test failure
- [ ] WebDriver managed automatically (no manual chromedriver downloads)
- [ ] Tests use explicit waits (no `Thread.sleep`)

```java
public class LoginScreen {
    private final AppiumDriver driver;
    private final WebDriverWait wait;

    public LoginScreen(AppiumDriver driver) {
        this.driver = driver;
        this.wait = new WebDriverWait(driver, Duration.ofSeconds(15));
    }

    // Android locators — use accessibility IDs when available
    private By emailField = AppiumBy.accessibilityId("email_input");
    private By passwordField = AppiumBy.accessibilityId("password_input");
    private By loginButton = AppiumBy.accessibilityId("login_button");
    private By errorMessage = AppiumBy.accessibilityId("error_message");

    public void login(String email, String password) {
        wait.until(ExpectedConditions.visibilityOfElementLocated(emailField));
        driver.findElement(emailField).sendKeys(email);
        driver.findElement(passwordField).sendKeys(password);
        driver.findElement(loginButton).click();
    }

    public String getErrorMessage() {
        wait.until(ExpectedConditions.visibilityOfElementLocated(errorMessage));
        return driver.findElement(errorMessage).getText();
    }
}
```

## Milestone 7: CI Pipeline

**Goal:** Run all tests automatically in Jenkins with Docker, producing consolidated reports and notifications.

**Estimated Time:** 10-12 hours

### Objectives

- Create a Jenkinsfile that runs API, web, and mobile tests in sequence
- Dockerize the test execution environment
- Configure parallel test execution within each stage
- Generate and publish consolidated Allure reports
- Add Slack or email notifications for failures

### Prerequisites

- [ ] Milestones 1-6 completed (all test suites exist and pass locally)
- [ ] Jenkins installed (or use Docker-based Jenkins)
- [ ] Familiar with Ci Cd Fundamentals from the CI/CD module

### Pipeline Stages


```groovy
pipeline {
    agent any

    stages {
        stage('Checkout') {
            steps {
                checkout scm
            }
        }

        stage('Start Backend') {
            steps {
                sh 'docker compose -f staynest-backend/docker-compose.yml up -d'
                sh 'sleep 30' // wait for backend to be ready
                sh 'curl --retry 10 --retry-delay 5 http://localhost:8080/api/v1/auth/signup || true'
            }
        }

        stage('API Tests') {
            steps {
                dir('staynest-api-tests') {
                    sh 'mvn test -Dbase.url=http://localhost:8080/api/v1'
                }
            }
            post {
                always {
                    junit 'staynest-api-tests/target/surefire-reports/*.xml'
                }
            }
        }

        stage('Web Tests') {
            steps {
                dir('staynest-web-tests') {
                    sh 'mvn test -Dbrowser=chrome -Dheadless=true'
                }
            }
            post {
                always {
                    junit 'staynest-web-tests/target/surefire-reports/*.xml'
                }
            }
        }

        stage('Report') {
            steps {
                allure includeProperties: false,
                       results: [
                           [path: 'staynest-api-tests/target/allure-results'],
                           [path: 'staynest-web-tests/target/allure-results']
                       ]
            }
        }
    }

    post {
        failure {
            slackSend channel: '#test-alerts',
                      message: "StayNest tests FAILED: ${env.BUILD_URL}"
        }
        always {
            sh 'docker compose -f staynest-backend/docker-compose.yml down'
        }
    }
}
```
