# Binary Search

> **Module:** 01-programming-foundations / dsa
> **Prerequisites:** Arrays And Strings, Complexity Analysis
> **Mastery Target:** L3

## Quick Overview (2-minute read)

**What:** Binary search is an O(log n) algorithm for finding elements in sorted data by repeatedly halving the search space.

**Why:** Binary search is a foundational interview pattern. Beyond classic "find the element," it's used for searching boundaries, minimizing/maximizing values, and bisecting failures. In automation, the same principle helps bisect which commit broke a build.

**Where:** Searching sorted arrays, finding boundaries (first/last occurrence), search insert position, rotated arrays, git bisect, binary search on answer.

<MentalModel>

Think of the dictionary game: someone picks a word, you open to the middle of the dictionary. If your target comes before the middle, you discard the second half. If after, discard the first half. Each step cuts the problem in half — that's why it's O(log n).

</MentalModel>


<KeyTakeaways>

1. **Prerequisite:** The data must be sorted (or have a monotonic property).
2. Use `mid = left + (right - left) / 2` to avoid integer overflow (not `(left + right) / 2`).
3. Three templates exist: exact match, left boundary, right boundary. Master the left-boundary template — it handles most cases.
4. O(log n) is incredibly fast: searching 1 billion elements takes only ~30 steps.
5. Off-by-one errors are the #1 bug — be precise about `left <= right` vs `left < right` and how you update `left`/`right`.

</KeyTakeaways>

## Key Patterns and Techniques

### Template 1: Classic Binary Search (Exact Match)


```java
public int binarySearch(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) {
            return mid;
        } else if (nums[mid] < target) {
            left = mid + 1;
        } else {
            right = mid - 1;
        }
    }
    return -1; // not found
}
// Time: O(log n) | Space: O(1)
```

**Key details:**
- `left <= right` — the search space includes both endpoints.
- `left = mid + 1` and `right = mid - 1` — always shrink by at least 1 to avoid infinite loops.

### Template 2: Left Boundary (First True)

Finds the first position where a condition becomes true. This is the most versatile template.


```java
// Finds the leftmost index where condition(nums[mid]) is true
public int leftBoundary(int[] nums, int target) {
    int left = 0, right = nums.length; // right is PAST the end
    while (left < right) {             // strict less-than
        int mid = left + (right - left) / 2;
        if (nums[mid] >= target) {     // condition: first element >= target
            right = mid;               // mid might be the answer, keep it
        } else {
            left = mid + 1;            // mid is too small, discard it
        }
    }
    return left; // left == right == insertion point
}
```

**Why this works:** When the condition is true, we keep `mid` as a candidate (`right = mid`). When false, we discard it (`left = mid + 1`). At the end, `left` points to the first position where the condition holds.

### Template 3: Search in Rotated Sorted Array


```java
// Determine which half is sorted, then decide which half to search
public int searchRotated(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;

        if (nums[left] <= nums[mid]) { // left half is sorted
            if (target >= nums[left] && target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else { // right half is sorted
            if (target > nums[mid] && target <= nums[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }
    return -1;
}
```

## Problems with Solutions

### Problem 1: Binary Search (LeetCode 704)

**Task:** Given a sorted array of integers and a target, return the index of the target or -1.

**Hint:** Classic binary search template. Be careful with `left <= right`.




```java
public int search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}
// Time: O(log n) | Space: O(1)
```



### Problem 2: First Bad Version (LeetCode 278)

**Task:** You have n versions [1, 2, ..., n]. Find the first bad version given an API `isBadVersion(version)`. Minimize API calls.

**Hint:** Left-boundary template. The "condition" is `isBadVersion(mid)`. You want the first `true`.




```java
public int firstBadVersion(int n) {
    int left = 1, right = n;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (isBadVersion(mid)) {
            right = mid;       // mid might be the first bad, keep it
        } else {
            left = mid + 1;    // mid is good, first bad is after
        }
    }
    return left;
}
// Time: O(log n) | Space: O(1)
```



### Problem 3: Search Insert Position (LeetCode 35)

**Task:** Given a sorted array and a target, return the index if found, or the index where it would be inserted.

**Hint:** This is exactly the left-boundary template — find the first element >= target.




```java
public int searchInsert(int[] nums, int target) {
    int left = 0, right = nums.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] >= target) {
            right = mid;
        } else {
            left = mid + 1;
        }
    }
    return left;
}
// Time: O(log n) | Space: O(1)
```



### Problem 4: Search in Rotated Sorted Array (LeetCode 33)

**Task:** A sorted array has been rotated at an unknown pivot. Search for a target in O(log n).

**Hint:** At each step, one half is always sorted. Determine which half is sorted, check if the target falls in that range, and eliminate accordingly.




```java
public int search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;

        if (nums[left] <= nums[mid]) {
            if (target >= nums[left] && target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else {
            if (target > nums[mid] && target <= nums[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }
    return -1;
}
// Time: O(log n) | Space: O(1)
```

## Common Mistakes

### Mistake 1: Integer Overflow in Mid Calculation


```java
// WRONG: can overflow when left + right > Integer.MAX_VALUE
int mid = (left + right) / 2;

// RIGHT: safe calculation
int mid = left + (right - left) / 2;
```

### Mistake 2: Infinite Loop from Wrong Update


```java
// WRONG: doesn't shrink the search space — infinite loop
right = mid;     // with while (left <= right)
left = mid;      // never moves forward if mid == left

// RIGHT: pair the correct condition with the correct update
// Template 1: left <= right → left = mid + 1, right = mid - 1
// Template 2: left < right  → left = mid + 1, right = mid
```

### Mistake 3: Confusing Templates


```java
// Using Template 1 (left <= right) when you need Template 2 (left < right)
// causes missed boundaries or off-by-one errors.

// RULE OF THUMB:
// - Need exact match? → left <= right, return mid when found
// - Need first/last occurrence? → left < right, return left at the end
```

## Automation Connections

| Concept | Automation Use Case |
|---|---|
| Binary search | Searching sorted test data efficiently |
| First Bad Version | `git bisect` — finding which commit broke the build |
| Search Insert | Finding where to insert a test in a priority-sorted queue |
| Boundary search | Finding the first failing test in an ordered test run |


```java
// Example: bisecting test failures in CI
// Given a list of commit hashes (oldest to newest), find the first one that fails
public String findFirstFailingCommit(List<String> commits) {
    int left = 0, right = commits.size() - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (runTestsForCommit(commits.get(mid)).hasFailed()) {
            right = mid;       // this commit fails, but an earlier one might too
        } else {
            left = mid + 1;    // this commit passes, failure is after
        }
    }
    return commits.get(left); // first failing commit
}
```

## Interview and Revision




**Q:** Why use `left + (right - left) / 2` instead of `(left + right) / 2`?
**A:** To avoid integer overflow. If `left` and `right` are both large, their sum can exceed `Integer.MAX_VALUE`.

**Q:** What's the difference between `left <= right` and `left < right` in binary search?
**A:** `left <= right`: search space can be 1 element, loop exits when space is empty. Used for exact match. `left < right`: loop exits when one element remains (the answer). Used for boundary search.

**Q:** How does binary search apply to `git bisect`?
**A:** `git bisect` binary searches through commits to find the first one where tests fail — exactly the "First Bad Version" pattern. Reduces O(n) commit checking to O(log n).

**Q:** What must be true about the data for binary search to work?
**A:** The data must be sorted, or more generally, must have a monotonic property — there's a clear boundary where a condition flips from false to true (or vice versa).
